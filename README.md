# Project 9: Vision-Based Precision Pose Estimation for Autonomous Formation Flying

Reimplementation of [Punnoose, Stanford CS229 (2020)](https://cs229.stanford.edu/proj2020spr/report/Punnoose.pdf).

**Team 9:** PES2UG24AM005, PES2UG24AM055

A follower aircraft's camera sees 14 known points on a leader aircraft. From those points we estimate the leader's relative pose in two stages:

1. An **ANN classifier** maps the 42 feature values (x pixel, y pixel, occluded flag for each of the 14 points) to one of 4800 coarse pose bins.
2. A **particle filter** refines that coarse guess over time using the flight dynamics.

All data is synthetic, generated by our own simulator. No external dataset is needed.

## Part 1: data + ANN classifier

Run these from the repo root, in order:

```bash
python tests/test_simulator.py              # 1. check the simulator (all PASS)
python src/generate_data.py --n 400000      # 2. generate data/dataset.npz (~5 s)
python src/train.py --epochs 40             # 3. train the ANN (1-2 min/epoch on CPU, stops early)
python src/plots.py                         # 4. figures -> results/figures/
```

What each step produces:

| Output | What it is |
| --- | --- |
| `data/dataset.npz` | `X` (N, 42) features, `y` (N,) labels, `poses` (N, 6) true poses, train/val indices |
| `models/pose_ann.joblib` | best model (by val accuracy) + input scaler |
| `results/metrics.json` | val accuracy, top-5 accuracy, % within one bin of the correct label |
| `results/training_log.csv` | loss and val accuracy per epoch |
| `results/error_distribution.npz` | val-set pose errors, used to initialise and resample the particle filter |
| `results/figures/` | Fig 4 / Fig 5 equivalents, training curve, camera views |

The random seed is fixed in `src/config.py`, so every step is reproducible.

If training gets interrupted, the best model so far is already saved. Continue with:

```bash
python src/train.py --resume --epochs 10
python src/train.py --eval-only             # rebuild metrics + error distribution from the saved model
```

### Part 1 results (validation set, 80,000 samples)

| Metric | Ours | Paper |
| --- | --- | --- |
| Exact bin accuracy | 29.0% | 54% |
| Top-5 accuracy | 75.1% | not reported |
| Within 1 bin in every dimension | 87.1% | not reported |
| Median abs error x / y / z / roll | 3.8 m / 3.0 m / 2.8 m / 4.3 deg | not reported |

Trained 13 epochs; validation accuracy plateaued at ~29% from epoch 11.
Our exact accuracy is lower than the paper's. Likely reasons: we add 1 px detector noise and
+-5 deg pitch/yaw variation the labels ignore (the paper's setup is noise-free as far as it states),
and a 2 x 100 network is small for 4800 classes. Most errors land in a neighbouring bin, which is
what the particle filter is designed to correct.
